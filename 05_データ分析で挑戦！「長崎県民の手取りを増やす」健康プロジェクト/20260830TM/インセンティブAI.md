### 検算結果

| 指標                                     | 結果                                   |

実測値は −0.21%〜+0.01%まで幅があるので、この誤差幅（RMSE 0.004pt）はかなり小さく、ロジックはほぼ正しく再現できていると言えます。

### 実装したロジック

1. **指標ごとに偏差値化**（平均50・標準偏差10）
   - 指標1・2は「実施率」「上昇幅」「上昇件数上昇率」を50%/25%/25%で加重
   - 指標4・5は「受診率／使用割合」「上昇幅」を50%/50%で加重
   - 指標3は「対象者減少率」単独
2. **「伸びしろ」調整**（資料13ページの記載）— ここが最初のCSV検算で外れた原因でした。「対前年度上昇幅」は生の数値ではなく、

```
   対前年度上昇幅 ÷ (100% − 当該支部の実績)
```

に変換してから偏差値化する必要があります（実績が100%に近い支部ほど、同じ上昇幅を高く評価するため）。これを入れないと上位15支部の判定が3支部もズレました。

1. **配点（70/70/80/50/50、合計320）で加重合計** → 総得点でランキング
2. **上位15支部を対象に、全支部一律+0.01%からの引下げを適用**

### 唯一の注意点

資料には「得点に応じた段階的な引下げ」を行うことは書かれていますが、**得点を具体的な引下げ幅（%）に変換する計算式そのものは公開されていません**。実際の制度では各支部の総報酬額（財源規模）も使って財源と支給額を均衡させていると考えられますが、そのデータはCSVに含まれていません。そのため`incentiveCalculator.ts`内の引下げ幅の一次式（`REGRESSION_A` / `REGRESSION_B`）は、検証用データへの回帰から得た**近似式**です（総得点との相関係数はR²≈0.99と非常に高いです）。順位判定・対象支部の選定ロジックは資料に忠実ですが、この部分だけは公式係数ではない旨、コード内コメントにも明記しています。

Linux環境で実行する手順です。実際にゼロから試して、ハマりそうな点も含めてまとめました。

### 1. 前提: Node.jsの確認

bash

```bash
node --version   # v18以上を推奨
npm --version
```

入っていなければ、Ubuntu系なら `sudo apt install nodejs npm`、または [nvm](https://github.com/nvm-sh/nvm) 経由でのインストールをおすすめします。

### 2. プロジェクトの準備

bash

```bash
mkdir incentive-ts && cd incentive-ts
npm init -y
npm install --save-dev typescript@5.6 ts-node @types/node
```

`incentiveCalculator.ts` と `verify.ts` をこのディレクトリに置きます。

**⚠️ 注意点（ハマりポイント）**: `typescript` を無指定でインストールすると最新の7系が入ることがありますが、`ts-node@10.9.2` は TypeScript 7系のAPI変更に対応しておらず、

```
TypeError: Cannot read properties of undefined (reading 'fileExists')
```

というエラーで落ちます。上記のように **`typescript@5.6`のように5系を明示指定** してください（実際にこの環境で再現・解決を確認済みです）。

### 3. tsconfig.jsonを作成

json

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "CommonJS",
    "esModuleInterop": true,
    "strict": true,
    "outDir": "dist",
    "resolveJsonModule": true,
    "types": ["node"]
  },
  "include": ["*.ts"]
}
```

### 4. CSVパスの確認

`verify.ts` 冒頭の

typescript

```typescript
const CSV_PATH = "/mnt/user-data/uploads/インセンティブ分析データ.csv";
```

を、お使いのLinux環境上の実際のCSVファイルパスに書き換えてください（例: `./data/インセンティブ分析データ.csv`）。

### 5. 実行

**方法A: ts-nodeで直接実行（お手軽）**

bash

```bash
npx ts-node verify.ts
```

**方法B: コンパイルしてからnodeで実行（より確実・高速）**

bash

```bash
npx tsc -p .
node dist/verify.js
```

どちらでも同じ結果になりますが、CI環境や依存関係が複雑な環境では方法Bの方がトラブルが起きにくいです。
